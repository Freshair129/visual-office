# Blender inspection of the existing Tycoon kit

The files in `derived/` are editable Blender **imports of the existing prototype GLBs**, not the original modeling masters. The original generators are `web/tycoon-models.js`, `web/studio-models.js`, and `web/office-characters.js`; runtime models remain the existing GLBs in `web/assets/models/tycoon/`. No derived file is used by the runtime automatically. Import may change mesh structure, joints or animation semantics; round-trip equivalence has not been established.

Blender 5.2.2 LTS (`d13f752e3b9c`) imported `desk`, `chair`, `floor`, `wall` and `actor`. Each has a `.blend`, an orthographic material preview and a JSON report with source SHA-256, dimensions, mesh count and imported actions. Blender uses Z-up and glTF/Three.js uses Y-up, so the dimensions are ordered differently. Preview images are inspection aids, not final art approval. These are not OFFICE_STANDARD or OFFICE_HERO assets.

To reproduce one import in a separate background Blender process from the repository root, substitute the installed Blender executable and choose a dedicated output directory:

```powershell
& 'G:\AI-Studio\Blender\blender.exe' -b --factory-startup --python-exit-code 1 -P scripts/asset-factory/inspect_blender.py -- web/assets/models/tycoon/desk.glb asset-source/blender/derived
node scripts/asset-factory/validate.mjs
node --test tests/asset-factory-validation.test.mjs tests/tycoon-assets.test.mjs tests/tycoon-scene.test.mjs
```

The import command replaces the named derived output files. It does not change the input GLB or the existing scene manifest. The Node validator checks GLB headers and JSON, internal resource references, IDs, sizes and hashes; it does not certify full glTF conformance, geometry, materials, animation playback, security against malicious inputs, or visual quality.

`derived/desk-qa.json` records a separate Blender asset QA run on the imported desk using the game profile. It **failed** with one detected coplanar overlap between Mesh_5 and Mesh_6 and recorded 28 warnings including overlapping UVs, duplicate vertices and hidden back-to-back surfaces. UV/vertex warnings can reflect GLB export seams and material-only use; they need investigation rather than automatic acceptance. Other assets have not received equivalent geometry QA. At the time of this import the actor had seven actions and no armature or skinned mesh; it was a rigid articulated prototype, not the requested reusable skinned rig. Since the 6 November character integration the regenerated prototype `web/assets/models/tycoon/actor.glb` carries two skins (garments), so these derived files no longer match it. Imported actions have not been round-trip or deformation tested.

The original inspection stage did not integrate new assets, a real roster, Open Question or approval action. See [the implementation plan](../../docs/superpowers/plans/2026-10-29-asset-factory-vertical-slice.md) for the asset, runtime, platform contract, quality and performance gates.

## 29 October follow-up: local rigged candidate

The Tycoon runtime loads `web/assets/models/tycoon-factory/desk-v3.glb` and `actor-rig-v3.glb` through versioned, hash-checked descriptors in `web/tycoon-factory-assets.js`. The actor is a generic **local simulation**; it carries no Agent identity, authority or runtime state. The existing seat/navigation system controls its world position. The original asset kit and scene state formats remain available.

- `desk-v3.blend` is an editable import derived from the existing `web/studio-models.js` generator, then refined by `scripts/asset-factory/refine_desk.py`. The [source geometry QA](desk-v3-qa.json) reports zero errors and warnings across 13 mesh objects. Hidden contact faces on the underside of attached desk accessories were removed; those meshes have intentional open boundaries and are not standalone watertight props. See `previews-v1/desk-v3.png`.
- `office-actor-rig-v3.blend` is generated by `scripts/asset-factory/build_actor.py` from the pinned original Tycoon prototype. It has a root plus 15 deform bones, 23 rigid single-bone-weighted meshes and 16 clips. It is not a smoothly skinned hero character. [Rig QA](office-actor-rig-v3-rig-qa.json) and [source geometry QA](office-actor-rig-v3-geometry-qa.json) report zero errors and warnings. UVs were unstacked and coincident source vertices welded; bilateral joints were aligned. See `previews-v3/` and the [motion samples](office-actor-rig-v3-motion.json).
- GLB round-trip QA still flags coincident-position vertices: [13 warnings on the desk](desk-v3-roundtrip-qa.json) and [23 on the actor](office-actor-rig-v3-roundtrip-qa.json). Attribute comparison at 1e-5 precision found 638 desk and 2,924 actor duplicate-vertex occurrences beyond the first vertex at each quantized position; every one has a different normal or UV, so welding them would change shading or UV seams. Blender's importer also creates an `Icosphere` in its `glTF_not_exported` helper collection; an [earlier unfiltered report](office-actor-rig-v3-roundtrip-with-helper.json) includes two warnings about that helper, which is absent from the Three.js scene. The filtered report checks all 23 exported mesh objects and reports ground z=0. The source QA and exported-GLB results are separate claims. This does not certify watertight geometry or visual approval.
- The existing Projects room provides four desk/chair stations. Station interactions shown in disconnected preview are explicitly simulation; no approval, question, Agent status or successful Zuri command is fabricated.
- The exported GLB regression samples both shoes at 30 Hz for idle, walk, sit, typing, wave and stand. Non-walk poses keep both feet within 5 mm of the floor; walking checks at least ten grounded intervals per foot and under 5 mm displacement per interval on a straight 0.85 m/s path. The default chair's seat is at 0.551132 m; a sampled seated pelvis is within 20 mm. Turning, route endpoints, other chair heights and physical-device visual acceptance remain separate checks.

## Follow-up: turns, endpoints and scaled custom chairs (29 October)

The 30 Hz straight-clip check above does not cover navigation heading changes or the station lifecycle. The existing Projects scene was measured on RTX 3060/WebGL in headless Chrome with the local simulated probe and a custom chair created from the existing chair GLB in a fresh browser context. [Measured data and source hashes](contact-scene-diagnostic-20261029.json) and [reproduction script](../../scripts/asset-factory/measure-contact-scene.cjs) describe the actual samples. No connected Agent or approval was created.

At this diagnostic checkpoint the issue was **unresolved**, not an acceptance pass. The runtime redesign below supersedes that implementation state. On the sampled orthogonal route, a planted foot moved up to 0.178 m between rendered frames at a turn; the first endpoint frame showed one foot up to 0.057 m above floor. During the 1.25-scaled custom-chair test, the authored seat height was 0.689 m and both feet were about 0.189 m above the floor during working; the pelvis bottom was about 0.740 m, 0.051 m above the authored anchor. The 0.9-scaled seat had an authored height of 0.496 m and working feet about 0.004 m below floor, while pelvis bottom was 0.547 m. The `done` phase was sampled only on its first rendered frame; no claim about its settled idle pose follows from it. Measurements are bounded to this route, model, frame sampling, chair asset and headless GPU/browser; the anchor height was supplied to the custom descriptor and is not an independent raycast of the seat mesh.

The earlier runtime translated the entire actor vertically for custom height and abruptly changed heading/animation at waypoints. Bundled scaled chairs and sofas also lack measured seat heights in station metadata. A trial CCD correction was rejected after full lifecycle sampling showed unreachable leg targets and residual contact errors; its runtime wiring was removed. A future correction needs a reachability-aware and continuity-preserving locomotion/seat design, measured built-in and custom anchors, and full walk/enter/sit/work/stand/leave and endpoint validation. The existing passing tests cover different, narrower behavior and do not close these findings.

## Runtime contact redesign — verified local slice (29 October)

`web/tycoon-contact.js` now owns lower-body posing: alternating world-space plants, lifted swing with zero endpoint velocity, bounded heading rotation and analytic two-bone IK with fixed limb lengths and a reachable pelvis. Existing clips retain upper-body motion. Feet reposition before sitting/standing and the activity waits for pose readiness. Missing rigs, unreachable targets, or a pose still unready after eight seconds stop the transient probe with an explicit message; they do not produce a success state. Exported GLBs are unchanged.

`web/tycoon-seat-contact.js` raycasts the assembled seat at the station anchor. Built-in chair/sofa metadata now scales with the object, and custom descriptors supply the expected height. The downward search is within 8 cm of that expectation and requires an upward near-horizontal surface. Actual measured seats outside 0.35–0.80 m are rejected for this actor. This does not mutate saved layout or assign business authority.

[GPU scene evidence and runtime hashes](contact-runtime-v1/report.json) cover ten cases: an orthogonal route plus bundled/custom chairs at scales 0.75 and 1.25, each at 30 and 60 Hz. Every case uses the production TycoonScene update path and renders every simulated frame on RTX 3060/D3D11, including all station phases and at least two seconds after reaching done. These are deterministic simulation steps, not a realtime performance benchmark. Contact pairs use a 1 mm floor threshold so a low airborne swing is not mislabeled planted. In these samples, planted displacement, working pelvis error and settled foot gap were all below 1 mm; measured seat surfaces were 0.413349 and 0.688915 m. See [large custom chair](contact-runtime-v1/custom-large.png), [small bundled chair](contact-runtime-v1/bundled-small.png) and [walking](contact-runtime-v1/route.png).

A separate [realtime hardware run](contact-runtime-v1/realtime-gpu.json) sampled ten seconds per mode at 1280×800 DPR1: 59.995 FPS / p95 16.8 ms and 29.997 FPS / p95 33.4 ms. This is rendered frame interval measurement on one headless browser/machine, not GPU execution time or VRAM. Run the static preview with `PORT=4197`, then `node scripts/asset-factory/verify-contact-scene.cjs <new-output-directory>`; the script refuses existing output directories. For realtime measurement, set `PREVIEW_PORT=4197` and run `node scripts/asset-factory/profile-gpu.cjs 10000`.

Verification: full `npm test` 460/460, no skips; corrected real 0.95 m pose-timeout regression also rerun directly; isolated `npm run build` passed with 490 embedded assets. Independent static review found no remaining blocker after invalid-rig, timeout and swing-envelope fixes. Source/report hashes were checked after the final run.

Remaining limits: root-path collision checks are preserved, but foot swings/knees/body are not swept against furniture and walls. Hands are not IK-matched to keyboard/armrests. Custom scene tests import the existing chair GLB through the custom loader, not a representative collection of arbitrary user models; only the authored anchor surface is raycast, not the whole pelvis footprint. Sloped/irregular seats, stairs, terrain, multiple actors and other skeletons are outside this test. The artist look/motion quality and other hardware remain open. Live Agent state, questions, approvals and production acceptance still require the separate Zuri contracts; no such state or approval was fabricated here.
