# Visual Office — Game Design v0.1

แนวทางภาพล่าสุด: อ่าน [Design sources](DESIGN-SOURCES.md) → Visual Office application profile สำหรับฉาก Painted 2.5D, เฟอร์นิเจอร์ Soft 3D และตัวละคร 2D Anime ส่วน economy ในเอกสารนี้ยังเป็นข้อเสนอเช่นเดิม

วันที่: 20 ตุลาคม 2026

สถานะ: ข้อเสนอสำหรับออกแบบและทดลอง — ยังไม่ใช่ระบบ economy ที่เปิดใช้จริง

ความคืบหน้าต่อจากรอบออกแบบ: [Design Studio — ห้องทดลอง 3D ชุดแรก](DESIGN-STUDIO.md) ใช้งานในเครื่องได้แล้ว โดยส่วน economy และการเชื่อม platform ยังอยู่ในขอบเขตข้อเสนอนี้

## 1. แนวคิดหลัก

**ออฟฟิศจำลองที่เติบโตไปกับงานจริง และเป็นพื้นที่ที่เจ้าของธุรกิจอยากกลับมาดูแล**

ผู้ใช้เข้ามาเห็นว่าวันนี้ธุรกิจมีเรื่องอะไรต้องดู ไปหาแผนกที่เกี่ยวข้อง เปิดงานหรือผลลัพธ์จริง แล้วค่อยใช้แต้มตกแต่งทำให้ออฟฟิศมีบุคลิกและสวยขึ้น ความสนุกมาจากการเห็นพื้นที่เปลี่ยนแปลง การสะสมชุดตกแต่ง และการเห็นผลงานของทีมปรากฏในโลกจำลอง

ประสบการณ์ควรเหมือน office idle บนมือถือ: เข้าใจจากภาพ แตะสิ่งของเพื่อใช้งาน มีการเคลื่อนไหวเล็กน้อย และมีสิ่งให้ปรับแต่ง โดยไม่บังคับเฝ้าจอหรือกดรับรางวัลตลอดเวลา งานธุรกิจต้องใช้ได้ครบตั้งแต่พื้นที่เริ่มต้น

### สิ่งที่พักไว้ตามคำสั่งผู้ใช้

- data model, API และ adapter ใหม่ของ Zuri
- การจัด domain/module ให้เป็นชั้นและพื้นที่ย่อยแบบถาวร
- จำนวน agent, role, การมอบหมาย และคำสั่งรัน agent
- การผูก reward เข้ากับเหตุการณ์จริงของ Zuri
- การสร้าง Business/Tenant/domain จากเกม

งานออกแบบนี้ไม่แก้ระบบที่รันอยู่ ไม่เปลี่ยน Business หรือสิทธิ์ และไม่แทนที่ข้อกำหนดที่ platform กำลังออกแบบ

## 2. แยกการเติบโตเป็นสองเส้น

| เส้นทาง | สิ่งที่ทำให้เติบโต | สิ่งที่เปลี่ยน |
| --- | --- | --- |
| โครงสร้างธุรกิจ | ข้อมูลที่ Zuri ยืนยัน | Business, domain, module, agent assignment |
| รูปลักษณ์สำนักงาน | การเลือกตกแต่งและแต้มใน Office | โต๊ะ เก้าอี้ วัสดุ แสง พื้นที่พัก สวน หน้าตึก |

การซื้อโต๊ะสวยขึ้นไม่เพิ่ม agent ไม่เพิ่มความสามารถของโมเดล ไม่เพิ่มสิทธิ์ และไม่เพิ่มเพดาน API การขยายห้องเพื่อจัดฉากไม่เท่ากับการขยายขอบเขตธุรกิจ

**กฎสำคัญ:** ถ้า Zuri เพิ่มทีมที่ได้รับอนุญาตเข้ามา Office ต้องแสดงทีมได้ทันที แม้ผู้ใช้ยังไม่มีแต้มตกแต่ง การซื้อพื้นที่ไม่เป็นเงื่อนไขให้เข้าถึงงานจริง

## 3. โลกของเกมและการขยาย

ตารางนี้เป็นภาพแทนชั่วคราวเพื่อออกแบบฉาก ไม่ใช่การตัดสิน data model ของ Zuri

| ภาพที่ผู้ใช้เห็น | ความหมายที่เสนอ | สถานะ |
| --- | --- | --- |
| แผนที่สำนักงาน / campus | กลุ่มอาคารของ Business ที่ผู้ใช้มีสิทธิ์ ภายในบริบท Tenant ที่เลือก | รอ platform ยืนยันขอบเขต; ไม่รวมข้าม Tenant เอง |
| อาคารหนึ่งหลัง | Business หนึ่งแห่ง | ค่าเริ่มต้นที่เสนอ |
| ชั้น G | Lobby / Business Home / จุดกระจายการเดินทาง | ทำฉากและการนำทางได้ |
| ชั้นสำนักงาน | domain ที่ Zuri เปิดให้ Business นี้ | รอ directory จาก Zuri |
| พื้นที่ย่อย / ห้อง | module หรือพื้นที่ทำงานภายใน domain | รอ taxonomy |
| ตัวละคร | agent instance และ role ที่ Zuri มอบหมายจริง | รอ roster; ไม่มีจำนวนตายตัว |
| โต๊ะว่าง / ห้องโชว์ | เฟอร์นิเจอร์หรือฉากตกแต่ง | ไม่อ้างว่ามี agent |

### เพิ่มชั้นอย่างไร

- เมื่อ Zuri ยืนยัน domain ใหม่: Office อาจต่อชั้นใหม่และเพิ่มชื่อในบอร์ดลิฟต์ โดยไม่หักแต้ม
- เมื่อผู้ใช้อัปเกรดออฟฟิศเดิม: เปลี่ยนวัสดุและขยายพื้นที่แนวนอนของชั้นเดิม ไม่เพิ่ม domain
- ถ้า domain มี module มาก: เพิ่มโซน ห้อง หรือปีกอาคารได้ หลัง platform กำหนดการจับคู่ ไม่สร้าง domain ใหม่เอง
- ชั้นจำนวนมากต้องมี directory ค้นหา/เลือกและการจัดกลุ่ม ไม่บังคับผู้ใช้เลื่อนภาพตึกทั้งหมด

### เพิ่มตึกอย่างไร

การมีงานมากขึ้นหรือยอดขายมากขึ้นยังไม่แปลว่าเป็น Business ใหม่ หาก Zuri ส่ง Business ใหม่ที่ผู้ใช้มีสิทธิ์ จึงเสนออาคารใหม่บนแผนที่ สาขาหรือสำนักงานแห่งที่สองของ Business เดิมต้องรอ platform แยก Branch/Location ให้ชัดก่อนใช้ภาพหลายตึก

ฉากสวน โรงจอดรถ คาเฟ่ หรือศาลาพักเป็นส่วนตกแต่งของ campus ได้ โดยไม่ต้องแปลงเป็นองค์กรหรือ Business

## 4. วงจรการเล่นและการทำงาน

### รอบสั้น: 30–90 วินาที

1. เข้าตึกแล้วมาถึง G เห็นสรุปเรื่องที่ควรดู
2. แตะบอร์ดงานหรือใช้ลิฟต์ไปแผนกที่เกี่ยวข้อง
3. เปิดสถานะ ผลงาน หรือคำขอจริงในแผงสั้น ๆ
4. กลับ Lobby พร้อมเห็นว่ามีอะไรเปลี่ยน ไม่ต้องเดินกลับผ่านฉากทุกจุด

### รอบทำงาน: 5–15 นาที

เลือกเรื่องสำคัญ → เปิดรายละเอียดและหลักฐาน → ดำเนินการตามสิทธิ์ผ่าน Zuri → เห็นผลตอบกลับจริง → รับรู้ความคืบหน้าผ่านฉากและบอร์ดผลงาน

หน้าที่รับเงินจริง อนุมัติธุรกิจ หรือสั่ง agent ในอนาคตต้องแยกจากปุ่มตกแต่งอย่างชัดเจน การแตะตัวละครเพื่อดูข้อมูลไม่ใช่การสั่งงานทันที

### รอบสร้างออฟฟิศ: หลายวันถึงหลายสัปดาห์

สะสมแต้มที่ได้รับแล้ว → เลือกเป้าหมายตกแต่ง → ลองจัดวาง → ยืนยันซื้อ → เห็นห้องเปลี่ยน → เก็บภาพออฟฟิศหรือชุดสะสม

ไม่มีการเสียหายของเฟอร์นิเจอร์เพราะไม่เข้าเกม ไม่มีค่าเช่าเสมือนที่ทำให้งานถูกล็อก และไม่มี streak ที่หายเมื่อหยุดพัก

## 5. ระบบอัปเกรด

### ระดับภาพรวม

| ระดับ | บรรยากาศ | สิ่งที่พัฒนา |
| --- | --- | --- |
| Starter | เล็ก สะอาด ใช้งานได้ครบ | โต๊ะเรียบ เก้าอี้พื้นฐาน แสงธรรมชาติ |
| Studio | อบอุ่นและมีเอกลักษณ์ของทีม | ไม้ พาร์ทิชัน ไฟ ต้นไม้ ที่เก็บของ |
| Signature | สำนักงานที่สะท้อนตัวตนของธุรกิจ | วัสดุพิเศษ แสงหลายชั้น lounge สวนหรือระเบียง |

ระดับเหล่านี้ใช้บอกงานศิลป์ ไม่ใช่คะแนนความสำเร็จของบริษัท ผู้ใช้เลือกสไตล์ที่ชอบได้ ไม่จำเป็นต้องตกแต่งทุกห้องเหมือนกัน

### เส้นทางซื้อที่เสนอ

| ของอัปเกรด | ราคาแต้มทดลอง | ผลที่เห็น | ขอบเขตการปลดล็อก |
| --- | ---: | --- | --- |
| Desk refresh | 120 | โต๊ะและเก้าอี้ชุดใหม่ | ใช้ซ้ำกับโต๊ะที่รองรับได้ทั้ง Business |
| Studio finish | 480 | ผนัง พื้น ไฟ และชั้นเก็บของ | ชุดตกแต่งสำหรับทุกชั้นที่รองรับ |
| Lounge extension | 900 | เพิ่มมุมพักหรือระเบียงข้างห้อง | layout variant ของชั้นเดิม |
| Signature exterior | 1,800 | เปลี่ยนวัสดุหน้าตึก ทางเข้า และสวน | รูปลักษณ์อาคาร Business เดิม |

ซื้อเป็น **สิทธิ์ใช้ชุดตกแต่งของ Business** ไม่คิดราคาต่อ agent หรือต่อโต๊ะที่เพิ่มใหม่ วิธีนี้ทำให้การปรับจำนวน role จาก Zuri ไม่ทำให้ผู้ใช้เสียของหรือถูกเก็บแต้มซ้ำ

ผู้ใช้ซื้อชิ้นไหนก่อนก็ได้ เส้นทางเรียงลำดับในแบบจำลองเศรษฐกิจเป็นเพียงตัวอย่างเพื่อวัดจังหวะการปลดล็อก

ของชิ้นเล็ก เช่น โคมไฟ กระถาง พรม และรูปติดผนังอยู่ช่วง 30–180 แต้มในชุดทดลอง แพ็กที่ซื้อแล้วสลับกลับไปมาได้ฟรี วางซ้ำได้ตามช่องวางของฉาก ไม่มีการขายคืนหรือการเก็งกำไรใน v0.1

### ขนาดห้อง

- Compact, Open studio และ Lounge wing เป็นรูปแบบพื้นที่ของชั้นเดียวกัน
- พื้นที่ทำงานที่จำเป็นต่อ roster จริงต้องปรับให้พอโดยอัตโนมัติ
- ส่วนที่ซื้อเพิ่มคือมุมพัก ระเบียง และพื้นที่จัดองค์ประกอบ ไม่ใช่จำนวนคนที่ใช้งานระบบได้
- ภาพตัวอย่างที่ใช้โต๊ะจำนวนเท่ากันทุกระดับมีไว้เทียบวัสดุเท่านั้น ไม่กำหนดว่า domain ต้องมีสี่ role

## 6. Economy v0.1

### ทรัพยากร

ใช้เพียงสกุลเดียว: **แต้มตกแต่ง** ของ Business ไม่ใช่ยอดเงิน รายได้ กำไร โทเคนโมเดล หรือคะแนนประเมินพนักงาน

เริ่มด้วย 300 แต้มต่อ Business สำหรับลองซื้อของครั้งแรก ไม่เติมใหม่เมื่อเปลี่ยนบัญชี เปลี่ยนเครื่อง หรือรีโหลดหน้า ไม่มีการโอนแต้มข้าม Business ในแบบแรก

### แหล่งที่มาของแต้ม

**ฐานที่แนะนำ:** งบตกแต่ง 200 แต้มทุก 7 วันต่อ Business โดยนับตั้งแต่เริ่มใช้ economy ครั้งแรก เพิ่มให้อัตโนมัติและไม่ต้องล็อกอินกดรับ เป็นกติกาของเกม ไม่ใช่เงินหรือรายได้จาก Zuri ทีมที่ไม่มีเหตุการณ์โบนัสก็ยังค่อย ๆ ตกแต่งได้ ในการเชื่อมจริง identity และสิทธิ์ของ Business ยังต้องมาจาก platform

**โบนัสผลงาน — สมมติฐานที่รอ Zuri:**

ตัวเลือกสำหรับทดลองคือ **ผลงานระดับ milestone ที่รับมอบแล้ว** ให้ 25 แต้มต่อเหตุการณ์ที่มีหลักฐานและผ่านเงื่อนไข สูงสุด 4 เหตุการณ์ต่อวันของ Business หรือ 100 แต้มต่อวัน

“milestone ที่รับมอบแล้ว” ในเอกสารนี้เป็นคำอธิบายด้านเกม ยังไม่ใช่ชื่อ event, endpoint, schema หรือสถานะที่ประกาศให้ Zuri ต้องรองรับ Platform ต้องยืนยันก่อนว่ามีเหตุการณ์ใดที่น่าเชื่อถือและเหมาะสมในแต่ละ domain

ไม่ให้แต้มจากจำนวน prompt, เวลาที่เปิดหน้า, จำนวน token, จำนวน task ที่สร้าง หรือการคลิกอนุมัติเฉย ๆ เหตุการณ์ต้องอ้างถึงผลลัพธ์ต้นทางที่ตรวจสอบได้ การแตกงานย่อยไม่ทำให้ milestone เดียวได้รับแต้มหลายครั้ง

การแจ้ง “ได้รับแต้ม” เป็นการแสดงรายการที่เพิ่มให้อัตโนมัติแล้ว ไม่ต้องกดรับจึงจะได้แต้ม และไม่ทำให้การตรวจรับงานเกิดขึ้นเอง

### เศรษฐกิจขณะไม่ได้เปิด Office

ถ้าในอนาคต Zuri มีผลงานที่ผ่านเงื่อนไขระหว่างผู้ใช้ไม่เปิด Office ระบบอาจสะสมโบนัสจากเหตุการณ์จริงเหล่านั้น เมื่อกลับมาจะแสดงใบสรุปผล งบตกแต่งรายสัปดาห์ยังเพิ่มตามรอบเวลา แต่ไม่แสดงว่าเป็นรายได้ธุรกิจหรือผลงานของ agent

แต้มไม่หมดอายุ ไม่มีเพดานบังคับให้เข้ามาเก็บทุกไม่กี่ชั่วโมง งบรายสัปดาห์ไม่ถูกตัดเมื่อหยุดใช้งาน เวลาและเพดานรายวันต้องใช้เวลาของ Business ที่ตกลงกับ platform ไม่ใช้เวลาจากเครื่องผู้เล่น

### ตัวเลขทดลองและจังหวะการปลดล็อก

ใช้เส้นทางซื้อ Desk → Studio → Lounge → Exterior และไม่นับการซื้อของชิ้นเล็ก:

| ผลงานที่ผ่านเงื่อนไขต่อวัน | โบนัส/วัน + งบ 200 ทุก 7 วัน | Desk | Studio | Lounge | Exterior |
| --- | ---: | ---: | ---: | ---: | ---: |
| 0 | 0 | วันแรก | 14 วัน | 42 วัน | 105 วัน |
| 1 | 25 | วันแรก | 7 วัน | 24 วัน | 56 วัน |
| 3 | 75 | วันแรก | 4 วัน | 14 วัน | 30 วัน |
| 4 หรือมากกว่า | 100 | วันแรก | 3 วัน | 10 วัน | 24 วัน |

ตัวเลขเป็นวันในแบบจำลองที่สมมติว่ามีจำนวนผลงานเท่ากันทุกวัน ไม่ใช่คำทำนาย productivity หรือเวลาที่รับประกัน ต้นทุนสะสมคือ 120 / 600 / 1,500 / 3,300 สูตรงบที่ได้รับรวมคือ `300 + 25 × min(ผลงานต่อวัน, 4) × วัน + 200 × floor(วัน / 7)` ราคาเหล่านี้เป็นตัวเลขตั้งต้นสำหรับ playtest

**เหตุผลที่เพิ่มงบประจำรอบ:** แบบทดลองที่ใช้โบนัสผลงานเพียงอย่างเดียวทำให้ทีมที่มี 1 ผลงานต่อวันต้องรอ 120 วันสำหรับเส้นทางครบชุด งบประจำรอบช่วยลดเหลือ 56 วัน และให้ทีมที่ไม่มีโบนัสยังมีความคืบหน้า ห้ามเร่งความเร็วด้วยการกระตุ้นให้แตกงานหรือรีบอนุมัติ

ยังต้องทดสอบว่าจังหวะนี้สนุกพอหรือไม่ โดยเฉพาะทีมที่ทำผลงานใหญ่เดือนละครั้ง งบพื้นฐานและโบนัสต้องปรับแยกกันได้ ช่วงรอข้อมูล Zuri สามารถทดลองกรณีโบนัส 0 ได้โดยไม่ต้องสมมติ API

### กติกาความคงที่

- เหตุการณ์ต้นทางเดียวได้รับแต้มครั้งเดียว แม้ส่งซ้ำ เชื่อมต่อใหม่ หรือมีหลายคนเปิด Office
- การรับมอบซ้ำหลังเปิดงานเดิมใหม่ไม่ให้รางวัลรอบใหม่โดยอัตโนมัติ
- ถ้าผลต้นทางถูกยกเลิกก่อนใช้แต้ม ให้ปรับรายการแต้มที่ยังไม่ใช้; ถ้าใช้แล้ว ไม่ทำยอดติดลบหรือยึดของโดยเงียบ ต้องมีสถานะตรวจแก้ที่อ่านเหตุผลได้
- การซื้อของกับการหักแต้มต้องสำเร็จเป็นรายการเดียว และรายการ retry เดิมไม่หักซ้ำ
- ทีมเลือกสิทธิ์จัดฉากและใช้แต้มแยกจากสิทธิ์อนุมัติธุรกิจ การออกแบบสิทธิ์จริงรอ platform
- ปิดระบบแต้มได้โดยยังใช้งานธุรกิจและดูฉากที่มีอยู่ได้

ระหว่างรอ Zuri ใช้เฉพาะ **Design sandbox** ที่ติดป้ายข้อมูลสมมติ ไม่มีการ mint แต้มใน Business จริง

## 7. Mobile idle UX

### Campus

เห็นตึกที่มีสิทธิ์และทางเข้า แตะตึกเพื่อเข้าชั้น G ชื่อ Business และบริบทที่เลือกต้องอ่านได้ชัด ฉากล้อมรอบช่วยให้รู้สึกเป็นย่านธุรกิจ แต่อาคารตกแต่งไม่เป็นเป้าหมายที่เปิดข้อมูลของบริษัทอื่น

### Lobby

มี reception, ลิฟต์พร้อม directory, บอร์ดเรื่องที่ต้องดู, lounge และมุมผลงาน งานสำคัญอยู่ที่บอร์ดเดียว ไม่กระจาย badge ทุกชิ้นของฉาก

### Floor

แตะโต๊ะหรือตัวละครเพื่อเปิดแผงข้อมูลด้านล่าง มีแผนกและสถานะข้อมูลกำกับ แถบลิฟต์ใช้เปลี่ยนชั้นได้ทันที ไม่ต้องรอเดินหรือดูแอนิเมชันจบ

### Decorate

แตะ “ตกแต่ง” → เลือกชิ้น → เห็นภาพก่อน/หลังและราคา → ลองวาง → ยืนยันซื้อ มีปุ่มกลับและยกเลิกชัดเจน การย้ายของที่มีแล้วฟรีและย้อนกลับการจัดวางล่าสุดได้

เมนูหลักที่เสนอสำหรับ mock: **ออฟฟิศ / ลิฟต์ / งาน / ตกแต่ง / ผลงาน** ชื่อและจำนวนเมนูยังทดลองได้ แต่ไม่เพิ่มเมนู economy แบบ dashboard หลายชั้น

### การเคลื่อนไหว

- เดินผ่าน ปลูกต้นไม้ แสงแดด ประตูลิฟต์ และเครื่องชงกาแฟเป็น ambient animation
- สถานะทำงาน/รอ/เสร็จที่ผูกกับ agent แสดงเฉพาะเมื่อมีข้อมูลจริงรองรับ
- ไม่มีการแสดงเปอร์เซ็นต์งานจากระยะเวลาที่ตัวละครนั่งพิมพ์
- ฉากพักเมื่อไม่อยู่ในหน้า; ลด motion ได้; ไม่มีเสียงที่เปิดเอง
- เมื่ออัปเกรด มีการเปลี่ยนวัสดุหรือวางเฟอร์นิเจอร์ 0.6–1.2 วินาทีโดยประมาณ ข้ามได้ ไม่ล็อกงานระหว่างรอ

## 8. ชุดฉากและโมเดลที่ทำได้ก่อน

### Foundation kit

พื้น ผนัง หน้าต่าง ประตู ลิฟต์ ราวบันได ป้ายว่าง เสารองรับ และชิ้นต่อมุม ใช้ประกอบห้องหลายขนาดได้ ไม่ฝังชื่อ domain หรือหมายเลขชั้นลง texture

### Furniture kit

โต๊ะ เก้าอี้ ที่เก็บของ ฉากกั้น โคมไฟ ต้นไม้ และกระดาน มีระดับ Starter / Studio / Signature ใช้ตำแหน่งวางและจุดนั่งร่วมกันเพื่อสลับโมเดลได้

### Shared-space kit

Reception, lounge, coffee corner, trophy shelf, information board และ roof garden ทำงานเป็นฉากกลาง ไม่ขึ้นกับชื่อหรือจำนวน agent

### Exterior kit

หน้าตึก ทางเข้าหลัก ฐานอาคาร ชั้นกลาง หลังคา ถนน ต้นไม้ รถ และทางเดิน ใช้ชั้นกลางซ้ำได้และเปลี่ยนจำนวนชั้นภายหลัง อาคารแยกเป็นชิ้นเพื่อไม่ต้องสร้างภาพใหม่ทุกครั้งที่ domain เปลี่ยน

### Character presentation kit

ท่ายืน เดิน นั่ง และอ่านเอกสาร พร้อมจุด attach ชื่อ/สถานะ การออกแบบรูปลักษณ์ทำได้ แต่ห้ามผูกสีชุดหรือรูปร่างเข้ากับ canonical role โดยยังไม่มีข้อตกลง

## 9. ทำอะไรต่อได้โดยไม่รอ platform

| ลำดับ | ชิ้นงาน | หลักฐานที่ต้องได้ |
| --- | --- | --- |
| A | ห้องทดลองหนึ่งห้องและโต๊ะสามระดับ | สลับรูปลักษณ์ได้โดยตำแหน่งนั่ง/ชื่อไม่เลื่อน |
| B | ชุด lobby/lift/ทางเดินแบบ modular | ห้องหลายขนาดและป้ายเปลี่ยนได้ |
| C | ระบบจัดฉากเฉพาะ sandbox | preview, place, cancel, undo และบันทึก layout ทดลอง |
| D | ทดลองราคาและจังหวะการปลดล็อก | ตัวเลขคำนวณซ้ำได้และเห็นความต่างของทีมงานถี่/ห่าง |

## 10. เกณฑ์ทดสอบแนวคิด

- ผู้ใช้ใหม่เข้าตึก → G → ลิฟต์ → ชั้นเป้าหมายได้โดยไม่ต้องอธิบาย
- ผู้ใช้แยกได้ว่าปุ่มใดดูงานจริง ปุ่มใดตกแต่ง และแต้มไม่ใช่เงินบริษัท
- การอัปเกรดไม่เปลี่ยนจำนวน agent สิทธิ์ หรือผลการทำงาน
- ห้องรองรับ roster ตัวอย่าง 0, 1, 4, 12 และ 40 ตัว โดยยังค้น/เลือกครบ ไม่ถือภาพสี่โต๊ะเป็นข้อจำกัดระบบ
- ที่ 320px ปุ่มสำคัญไม่ทับกัน บอร์ดลิฟต์อ่านได้ และพื้นที่ทำงานไม่ถูกบังคับให้ผ่านฉาก
- ข้อมูลช้าหรือขาดการเชื่อมต่อแสดงเป็นยังไม่ทราบ ไม่มีข้อความ “กำลังทำงาน” จาก animation อย่างเดียว
- งานที่ส่งซ้ำ การซื้อที่ retry และการกลับเข้าระบบไม่เพิ่ม/ลดแต้มซ้ำ
- ผู้ใช้ที่กลับมาหลังหยุดพักยังมีของเดิมและไม่มีหนี้ในเกม
- ทดลองกับทีมงานที่มีผลงานน้อยแต่ชิ้นใหญ่ก่อนตัดสินอัตรา reward

## 11. สิ่งที่ต้องได้คำตอบจาก Zuri ก่อนเชื่อมจริง

ต้องการความหมายของ Business/Tenant/domain/module, identity และ assignment ของ agent, ผู้มีสิทธิ์เห็นและจัดการแต่ละส่วน, เหตุการณ์ผลงานที่ยืนยันได้พร้อมการยกเลิก/แก้ไข, และสถานะ runtime ที่เชื่อถือได้

รายการนี้เป็นความต้องการข้อมูลระดับ product ไม่กำหนดชื่อฟิลด์ ตาราง หรือ endpoint ให้ platform การออกแบบ API และ data model ทั้งหมดพักอยู่ตามคำสั่งผู้ใช้

## 12. สถานะส่งมอบรอบนี้

ได้ Game Design v0.1, art-production brief, ตัวเลข economy ที่ตรวจคำนวณได้ และภาพคอนเซ็ปต์การตกแต่ง ไม่มีการเปลี่ยน Office ที่รันอยู่ ไม่มีโมเดล 3D ใหม่ที่อ้างว่าพร้อมผลิต และไม่มีการผูก reward กับข้อมูลธุรกิจจริง

ตรวจสูตรกับการสะสมรายวันแยกกันครบ 605 กรณี (5 ระดับผลงาน × วันที่ 0–120) ตารางวันปลดล็อกตรงกัน ตรวจการเปลี่ยนตัวเลือกและ slider ในเบราว์เซอร์แล้ว รวมกรณีไม่มีโบนัสและเกินเพดาน ตรวจหน้าตัวอย่างที่ความกว้าง 736px และ 320px โดยเนื้อหาไม่ล้นแนวนอน ผลนี้ยืนยันเฉพาะแบบจำลองออกแบบ ไม่ใช่การทดสอบ economy หรือ 3D ใน Office จริง
